# 네이버 스마트에디터 ONE 자동화 — 부딪혀서 알아낸 것들

`scripts/naver/publish.py`가 네이버 블로그에 글을 올릴 때 걸린 함정들을 적어둔다.
공식 문서에 없는 내용이라 실계정으로 직접 확인한 것이고, 다음에 에디터가 바뀌어
깨졌을 때 여기부터 보면 된다.

## 전제 — 글쓰기 API는 없다

네이버는 블로그 글쓰기 공개 API를 오래전에 닫았다. 브라우저를 띄워 에디터를
조작하는 것 외에 방법이 없다. 그래서 `publish.py`는 Playwright로 돈다.

로그인과 발행은 분리했다. 로그인은 사람이 한 번(`login.py`, 브라우저가 뜨고 직접
로그인), 발행은 그 세션 파일만 읽어 headless로 매번. 아이디·비밀번호를 스크립트에
넣지 않는 건 네이버가 자동 로그인을 봇으로 보고 캡차를 띄우거나 계정을 잠그기
때문이다. 세션 파일 하나면 로컬과 클라우드에서 같은 코드가 돈다.

---

## 1. `has-text`는 부분 문자열 매칭이다 — 취소선 사건

**증상:** 발행된 글 전체에 취소선이 그어졌다.

**원인:** "이어쓰기" 팝업을 닫으려고 이렇게 썼다.

```python
"restore_popup_cancel": [".se-popup-button-cancel", "button:has-text('취소')"]
```

Playwright의 `has-text`는 부분 문자열로 매칭한다. 팝업이 없는 날에는 두 번째
후보가 **툴바의 "취소선" 버튼**을 눌러버린다. 그 상태로 타이핑하니 글 전체에
취소선이 켜졌다.

**교훈이 하나 더 있다.** 이때 "네이버가 외부 HTML 붙여넣기를 `<strike>`로 감싼다"고
잘못 진단했다. `<p>`, `<div>`, `<strong>`, `<span style>` 여섯 가지를 다 시험해
전부 취소선이 나왔으니까. 하지만 **모든 시험이 이미 취소선이 켜진 상태에서 돌아간
것**이었다. 원인을 고치고 재보니 붙여넣기는 멀쩡했다. 재현 실험을 오염된 상태에서
돌리면 엉뚱한 범인을 잡는다.

**대응:** 팝업 전용 클래스만 쓴다. 토글 버튼이 있는 툴바 근처에서 `has-text`를
쓰지 않는다.

## 2. HTML 소스 편집 모드는 없지만, 붙여넣기는 변환된다

스마트에디터 ONE에는 HTML 편집 탭이 없다. iframe·임베드를 문자열로 꽂을 방법이
없다.

대신 **클립보드에 `text/html`을 담아 붙여넣으면** 에디터가 그걸 파싱해 자기
컴포넌트(소제목·굵게·목록)로 바꿔준다. HTML을 "넣는" 게 아니라 "붙여넣어
변환시키는" 것이다. `md_to_html()`이 이 용도다.

클립보드를 쓰려면 컨텍스트에 권한을 줘야 한다.

```python
ctx.grant_permissions(["clipboard-read", "clipboard-write"],
                      origin="https://blog.naver.com")
```

## 3. 구글맵은 '장소' 카드로 들어간다

iframe으로는 못 넣지만, 툴바의 **장소** 버튼으로 붙이면 된다. 그리고 **해외 장소는
네이버가 구글 Static Maps로 렌더한다** — 발행된 글의 DOM을 보면
`se-placesMap` 컴포넌트 안에 `maps.googleapis.com/maps/api/staticmap` 이미지가 있다.

즉 "네이버 블로그에 구글맵 넣기 = 장소 카드 붙이기"다. 국내 가게든 해외 가게든
이게 정답이고, 검색 노출에도 유리하다.

장소 카드를 붙이는 절차에 함정이 셋 있다.

**검색 범위가 기본 "국내"다.** 일본 가게를 그대로 검색하면 0건이 나온다.
`.se-popup-button-map-place`를 눌러 "해외"로 바꿔야 한다. `naver.md`의
`place_region:` 항목이 이걸 지정한다.

**검색창이 react-autosuggest다.** `fill()`로 값을 꽂으면 React의 onChange가 돌지
않아 검색이 아예 실행되지 않는다. `page.keyboard.type()`으로 진짜 타이핑해야 한다.

**"추가" 버튼은 hover해야 나타난다.** 결과 항목(`.se-place-map-search-result-item`)에
마우스를 올려야 `.se-place-add-button`이 보이고, 그제서야 클릭된다. 항목 링크를
클릭하는 것만으로는 "확인" 버튼이 활성화되지 않는다.

## 4. 팝업이 안 닫히면 발행 버튼이 안 눌린다

장소 팝업을 "확인"으로 닫지 않으면 `.se-popup-dim` 오버레이가 남아서 발행 버튼
클릭을 가로챈다. 에러 메시지가 "발행 버튼을 못 찾았다"가 아니라 "다른 요소가
포인터 이벤트를 가로챈다"로 나오므로, 이 증상을 보면 앞 단계의 팝업을 의심한다.

## 실패했을 때

`publish.py`는 선택자가 빗나가면 **종료 코드 4**로 멈추고 글 폴더에
`publish-failure.png`를 남긴다. 반쯤 쓰다 만 글이 발행되는 일은 없다.
스크린샷을 보고 `publish.py` 상단의 `SEL` 딕셔너리만 고치면 된다. 항목마다 후보
선택자를 리스트로 받아 위에서부터 시도한다.

DOM이 통째로 바뀌었으면 헤드리스로 에디터를 열어 실제 클래스 이름을 떠보는 게
제일 빠르다. 오늘 장소 카드 선택자도 그렇게 찾았다.

## 종료 코드

| 코드 | 뜻 | 할 일 |
|---|---|---|
| 0 | 발행 성공 | stdout에 `{"url": ...}` |
| 1 | 입력 오류 (형식·사진 경로·본문에 `[확인 필요]` 잔존) | `naver.md` 확인 |
| 2 | 세션 파일 없음 | `login.py` 먼저 |
| 3 | 세션 만료 | `login.py` 다시 |
| 4 | 선택자 빗나감 | 스크린샷 보고 `SEL` 수정 |

## 아직 안 한 것

- **카테고리 지정.** 지금은 블로그 기본 카테고리로 들어간다.
- **공개 설정.** 지금은 전체공개 기본값. 비공개로 먼저 올려 확인하는 흐름이 필요하면
  발행 패널의 공개설정 선택자를 추가해야 한다.
